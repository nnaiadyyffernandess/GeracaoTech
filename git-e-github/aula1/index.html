Esse é apenas um teste:

Estamos salvando as alterações no git.

O crtl " acessa o terminal. Sempre escolha abrir pelo bash ao invés do powershell, pois é mais explicativo.

O comando no terminal git status mostra os commits, o estado do arquivo.

git add index.html : adiciona uma modificação, atualização prontas para serem comitadas. Você adicionou a alteração dentro da bolsinha, por assim dizer. Esse comando pede que usemos o nome do arquivo

git reset: tira qualquer atualização

Quando houver vários arquivos, para não repetir várias vezes o git add, podemos fazer git add . , ele adiciona todos os arquivos da pasta.

O próximo passo é comitar: git commit -m "Primeira interação"

E o git push envia os commits para o repositório

Então veja a sequência correta:

  1. git add . -> Inclui na "bolsinha" as alterações
  2. git commit -m "descrição das alterações" -> registra essas alterações no histórico
  3. git push -> envia os commits para o github

Alguns comandos importantes:

  • ctrl " -> abre o terminal

Entenda as branches:

As branches permitem testar versões alternativas, sem comprometer o código original.

  1. git status -> para confirmar que está na versão original
  2. git checkout -b nomedabranchalternativa -> criar uma branch alternativa
  3. git branch -> verificar se está na branch alternativa
